# 🌲 Evergreen Algotrading System - Operational Workflow Guide

Welcome to the **Regime-Aware Strategy Orchestrator (Evergreen Edition)**. This guide explains how to operate, monitor, and optimize your trading system which dynamically adapts to Bull, Bear, Range, and Panic markets.

## 🏗️ System Architecture

The core of the system is the **Strategy Orchestrator** running on Freqtrade. It behaves like a Hedge Fund Manager, selecting the best sub-strategy for the current regime.

| Regime | Condition | Active Strategy | Leverage | Goal |
| :--- | :--- | :--- | :--- | :--- |
| **🐂 Bull** | Price > SMA200 & ADX > 20 | **Trend Long** (WMA Cross) | **High (8x)** | Maximize Gains |
| **🐻 Bear** | Price < SMA200 & ADX > 20 | **Trend Short** (Inverse WMA) | **Medium (5x)** | Profit from Drops |
| **🦀 Range** | ADX < 20 | **Mean Reversion** (Aroon) | **Medium (5x)** | Scalp Volatility |
| **🛑 Panic** | ATR > 2x Avg | **Cash Safety** (Exit All) | **0x** | Prevent Liquidation |

## ⚙️ Workflow 1: Configuration

Your control center is `user_data/config.json` and strategy parameters.

### 1. Key Config Settings (`config.json`)

* **`dry_run_wallet`**: Set your starting capital (e.g., 100 USDT).
* **`max_open_trades`**: Recommended **3-5** for diversification.
* **`pair_whitelist`**: Add high-volume pairs (XRP, DOGE, SOL, BTC).

### 2. Strategy Parameters (`StrategyOrchestratorStrategy.py`)

To adjust risk without coding, find these lines:

```python
bull_atr_multiplier = 1.5   # Tighter Stoploss = Lower Value
bull_risk_reward = 3.0      # Higher Reward Target = Higher Value
```

## 🧪 Workflow 2: Verification (Backtesting)

Always verify changes before deployment.

### Step 1: Download Data

Fetch the last 200 days of data to test all regimes.

```powershell
docker compose -f infrastructure/docker-compose.backtest.yml run --rm freqtrade-backtest download-data --pairs XRP/USDT:USDT DOGE/USDT:USDT --days 200 -t 1h
```

### Step 2: Run Backtest

Execute the Orchestrator strategy on the downloaded data.

```powershell
docker compose -f infrastructure/docker-compose.backtest.yml run --rm freqtrade-backtest backtesting --config user_data/config.json --strategy StrategyOrchestratorStrategy --timerange 20250701-
```

### Step 3: Analyze "The Log"

Check `user_data/backtest_debug.log` to see which strategies are triggering:

```bash
python scripts/analyze_regime_log.py
```

*Look for:*

* **Regime Distribution**: Is it mostly Range?
* **Trade Execution**: Are `bear_wma_short` trades happening during drops?

## 🚀 Workflow 3: Live Operation

### 1. Start the Bot

```powershell
docker compose -f infrastructure/docker-compose.backtest.yml up -d
```

### 2. Monitor Panic Mode 🛑

If the market crashes (e.g., Bitcoin drops 10% in an hour), the **Panic Watchdog** in `regime_detection.py` will trigger.

* **Effect**: All positions closed, new entries blocked.
* **Action**: Check logs for `PANIC` regime detection. Do **NOT** manually override unless you are certain the crash is a fake-out.

### 3. Telegram Reports

Use the reporting script to get a summary of performance at any time (requires setup):

```powershell

```

## 🧠 Workflow 4: "Evergreen" Maintenance

### Monthly Routine

1. **Scan for New Pairs**: Use Hyperopt or manual research to find new volatile pairs.
2. **Re-optimize Params**: Run a 30-day Hyperopt on the *latest* data to tune `bull_wma_short` and `bull_wma_long`. Market rhythms change!

### Handling "Drawdown"

If you see > 15% Drawdown:

1. **Don't Panic**: Check if it's "Choppy" (Range) or "Crash" (Bear/Panic).
2. **Adjust Leverage**: Reduce global leverage in `StrategyOrchestratorStrategy.py` from 5.0 to 3.0.
3. **Tighten Stops**: Reduce `range_atr_multiplier` to 1.0.
